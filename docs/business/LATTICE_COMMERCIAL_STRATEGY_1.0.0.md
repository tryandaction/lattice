本轮已完成的是事实盘点、模型重建、任务拆解和算术校核。所有用户访谈、真实模型评估、商户接入、发布、收款和复购均须留下后续原始记录，不能由规划代填。

### 0.1 前三件具体动作

1. 创始人填写可投入周历、最高可承受试验损失和模型预算；确认现在是否仍有每周 8 小时。无法提供资金或时间时，保持免费本地项目，不启动官方收费服务。
2. 在同一研究群体约 6 位目标用户，收集其最近一次论文任务和现有替代流程；对其中 3 人用现有候选做真实共读观察。
3. 只有重复痛点和真实共读价值出现，才启动至多 40—60 工时的商业链路增量。开发期间不新增无关功能；第 90 个日历日复盘是否值得继续。

### 0.2 什么才叫“闭环”

合格用户触达 → 用户用自己的材料完成任务 → 看清开源/官方服务差异与价格 → 实际付款 → 权益到账 → 真实服务交付 → 成果留在本地 → 故障/退款可处理 → 到期主动再买 → 核算每单收入、成本和工时 → 只扩大有贡献的渠道。

上述箭头逐项有责任人、证据和异常出口，才是经营设计闭合。只有真实交易与复购出现，才是商业闭环成立。当前后者尚未成立，不能用增加文档或替换套餐名宣称成立。

## 2. 客户、任务与替代方案

### 2.1 第一批客户筛选

同时满足：成年；使用 Windows；近期有自己要读的文本 PDF；每周至少一次需要留下阅读成果；能展示目前如何查原文和整理笔记；愿意参加一次任务观察。付费样本优先来自已为软件、模型或资料服务实际付过钱的人，而非泛学生群体。

首轮不以学科总人数估市场。选择一个可触达研究群体；只有在其中重复发现同一类痛点，才考虑相邻方向。未发表、受限或不允许发送给第三方的材料，继续本地阅读或获准的本地模型路径，不进入官方托管体验。

一份有效任务记录必须包含：最近一次具体任务、原工具和顺序、卡点、实际用时、成果形态、原有支出、材料发送边界。只说“AI 很有用”不算需求证据。

### 2.2 工作流竞争，而非功能数量竞争

| 用户现有选择 | 已经满足的需要 | Lattice 必须证明的新增价值 |
| --- | --- | --- |
| Zotero/其他文献管理器 + 通用 AI + Markdown | 管文献、解释、写笔记 | 同一选区的来源和笔记不反复搬运；成果能关联并继续 |
| 独立 PDF AI 阅读器 | 问答、概要和引用 | 原位批注审阅、实际写回、重开与任务连续性更可靠 |
| 原有阅读习惯 | 无迁移成本、信任熟悉工具 | 一个完整任务中有可感知收益，迁入/导出不形成负担 |
| Lattice 开源版 + 自备模型 | 可自行控制软件和供应商成本 | 官方服务免配置且有明确额度、故障处理和持续运维 |

不能只说“我们也有引用”。用同一个难度相近的任务记录原流程与 Lattice 的完成时间、原文核对、手工搬运次数及笔记重开情况；顺序交替，注明带教和熟悉效应。5 人里至少 3 人既能完成，又能说出会在下一次使用的理由，才继续。

本轮尝试读取竞品官方页面，但网络不可用；未核实其当前价格，不进行“比某竞品便宜多少”的宣传或精确价格比较。官方核验入口保留在第 19 节。

### 2.3 用户与付款人分开

个人包：实际阅读者自行付款，不依赖报销。课题组：导师、项目负责人或管理员可能采购，但预算、合同、发票、跨境/供应商和成员权限要求均需另外验证。课题组收入暂按 0 记，不用于证明首个个人方案可以盈利。

## 3. 产品形态、品牌与体验

### 3.1 一个桌面主任务，一个清楚入口

正式技术产品继续是 Lattice 格致，格子是其中的 AI 科研搭子。用户首屏优先看到“打开论文继续共读”；PDF、格子面板、少量批注草稿与阅读笔记组成主路径。代码、Notebook、插件和皮肤作为高级功能保留，不要求用户在首篇论文前理解完整工作台。

网页承担准确介绍、真实录屏、支持范围、官方服务与本地版区别，以及一个试用/下载入口。公开实时 Web AI 是独立项目，本版不建设。当前已有技术应用页面不等于商业营销页，现状见 FACTS.md。

### 3.2 保留品牌方向，改变价值证明方式

- 品牌句：格子，你的科研搭子。
- 解释句：一起读懂一个问题，回到原文，把想法留下来。
- 专业性：明确来源、读取范围、失败状态；不把猜测写成事实，不把草稿写成已保存。
- 情绪价值：耐心、允许不懂、可关闭主动提示、尊重用户节奏；不靠拟人依赖留人。
- 视觉：安静、清楚、正文优先；沿用现有图标与默认浅/深色，不在商业链路成立前重做全套吉祥物/动画。

品牌、域名及商标权益尚未完成专业核验；没有证据时不宣称名称独占。对外禁止“零幻觉、所有论文读懂、最佳、无限 AI、替代导师、自动发论文”等表达。

### 3.3 一次成果的最低组成

用户自己的问题；引用的页/段；事实与解释区分；用户确认的最多 5 条批注；一份可编辑笔记；未解决问题和下次入口。关闭重开仍能找到成果，导出无需付费。来源定位可检验不代表解释必然正确，重要判断仍由用户核实。

## 4. 开源与收费边界：下载以后为什么还会付钱

根目录标准 MIT 与第三方组件的实际范围仍须审查，见 FACTS.md。对有效按 MIT 授权的自有代码，用户可以按许可使用、修改、构建和再分发；也允许收费出售副本。不存在“MIT 法律上要求所有本地功能永远免费”的结论。

本版选择免费本地核心，是为了降低体验和信任门槛；不是法律被迫。单靠销售已公开代码的下载许可、隐藏一个本地开关或强制联网解锁，容易被替代，因此不作为首期收入支柱。

| 层 | 用户可免费取得什么 | 收费对象/边界 |
| --- | --- | --- |
| 本地开源软件 | 实际授权范围内的阅读、编辑、批注、笔记、导出、BYOK；也可自行构建 | 免费下载本身没有收入；BYOK 模型费由用户自己的供应商收取 |
| 官方共读服务 | 受邀请用户的一次有限官方体验 | 认证用户调用官方运行的模型路由、任务编排和额度；官方承担运行与故障责任 |
| 官方发行与品牌 | 本版仍提供免费官方客户端 | 签名、更新、来源声明和质量是信任投入，不声称 MIT 禁止他人复制代码 |
| 机构运营 | 自行部署代码按实际许可处理 | 将来可以销售部署、运维、组织账户、支持和合同责任；不是剥夺自托管权 |
| 创作者材料 | 作者合法授权的资料、方法和技能包 | 作者自己的知识产权、审核与交易服务；不是出售用户论文或私人对话 |

MIT 若覆盖同仓 Workers，自托管者可以复用服务代码；不能把该源码保密当护城河。免费用户不一定转付费，熟悉技术且已有模型账户的人可能永远 BYOK，这属于本版接受的客户分层。

付费理由必须真实：无需申请/配置模型账号，当前任务入口直接可用，模型与发送范围清楚，费用可预测，失败有退出/补偿，成果继续可用。若用户仅需要免费本地版，或通用 AI 已足够，就不应强迫购买。

### 4.1 三条商业路线的取舍

| 路线 | 当前判断 |
| --- | --- |
| 单卖桌面安装包/源码许可 | 可以依法销售，但自由再分发和免费替代使排他性弱；不作为第一收入模型 |
| 免费本地核心 + 官方共读服务 | 选为当前唯一试点；卖实际运行的整段任务体验与便利，但接受用户自行部署和替代风险 |
| 一开始做课题组私有部署、社区和创作者平台 | 采购、权限、运维、双边交易与支持过重；只做购买者研究，不并行建设 |

如果创始人不愿经营持续服务，或官方服务不能证明需求，正确退出是维持免费开源工具或另案调整尚未授权的新业务；不能假装只改许可证就追回已授权代码或已经获得商业壁垒。本轮不修改 LICENSE，也不改变任何已有授权。

## 5. 唯一首发商品合同

以下是拟议的受控商业试点规格，不是当前已上线能力。模型、预算、数据政策和履约能力通过第 8 节后，才可显示购买按钮。

| 项目 | 唯一定义 |
| --- | --- |
| 商品 | 格子官方共读包，个人使用；一个账户一个并发任务 |
| 首个真实报价 | 99 元/30 天；同一试点队列同价。不是已验证市场定价 |
| 包内数量 | 20 次有效共读；界面同时显示剩余次数和具体到期时间 |
| 单次范围 | 一份可提取文字 PDF，最多 20 页、20 MiB；最多 5 轮围绕该文献的问答、最多 5 条批注草稿、一份不超过 2,000 汉字的研究笔记 |
| 资源范围 | 单次全部模型调用合计最多 100,000 输入 token、10,000 输出 token；重试也计入资源/费用。前置检查无法在该范围履约时不启动 |
| 交付判定 | 有可读正文、可检验引用、用户审阅的草稿及可重开的笔记；失败/取消规则见第 7 节，不能仅以模型请求成功判交付 |
| 用户启动前看到 | 服务模型/版本、材料发送范围、供应商处理政策、消耗 1 次的含义、剩余额度、取消入口 |
| 计时 | 付款核验并成功开通时开始连续 30 天；不能开通则不计时并退款 |
| 到期/续购 | 无自动续费；用户明确再买。到期关闭官方调用，本地文件、BYOK、导出和历史成果继续可用 |
| 不包含 | 云盘/个人跨设备同步、灾备 SLA、课题组组织功能、扫描 OCR、无限长文、多篇自主综述、代码执行、任意技能市场 |
| 客服 | 受控试点工作日 2 个工作日内初次回复；不承诺 24×7。若实际无法兑现就停止新售 |
| 年付/点数/多档套餐 | 首期不做；避免预收一年服务却尚无续购和成本证据 |

“20 次”是 20 个有边界的共读任务，不等于 20 次 HTTP 请求。服务端以任务 ID 记录开始、预留、交付、失败及恢复，聊天重开不重新扣费，也不能绕过账户总额度。文件更换或超出范围前显示是否需要新任务；不能静默拆成多次收费。

上线前必须选定一个通过质量评估的模型版本并锁定本队列的服务范围；不临时更换为更差模型来压成本。供应商价格与材料政策未核实、成本不可计量或质量不达标时，商品保持未开放。

### 5.1 免费体验与 BYOK 的关系

受邀请用户可在 7 天内试一次同规格官方共读，不要求绑卡或自备密钥；重复申请受账户规则约束，不开启公共无限试用。该试用消耗归获客试验成本，不计付费收入。

本地和 BYOK 已有能力继续免费；BYOK 用户不消耗官方次数，也不得被官方订阅锁住本地能力。官方体验需要隐私告知和经批准的模型预算，未批准就只做非 AI 观察，不计为官方核心价值验证。

### 5.2 为什么是 99 元而不是先前 29 元

本版假设每 30 天支付/退款/税务现金预留共占标价 11%，AI（含失败预留）15 元、每用户基础设施增量 2 元；若希望现金贡献至少为标价 70%，则 P×(1−0.11)−17≥0.70P，P 至少约 89.47 元。99 元留出少量余地。

这是成本可行性下界，不是用户愿付价格。模型费假设必须被真实计费替换；如果合格用户不愿以 99 元购买这个交付，不能因为算式好看就认定商业成立。也不能靠承诺无限量或隐去模型费用促成成交。

## 6. 最小商品化范围与工程差距

### 6.1 当前能力与规划增量分开

| 项目 | 当前证据 | 首期处理 |
| --- | --- | --- |
| PDF 阅读、批注、笔记、AI 工具与来源机制 | 存在实现和近期候选验收；真实回答质量未被本轮重测 | 复用；只修阻断既定共读任务的问题 |
| BYOK 与多供应商连接 | 已有 provider profiles；当前默认隐私字段包含多个上下文范围 | 复用连接层；官方模式需单独收窄发送范围，不能沿用宽默认即宣称最小发送 |
| 共享库 | 有生产部署及合成验收 | 保留；本次个人共读服务不依赖云存储，不把它包装成已运营灾备 |
| 官方托管模型收费入口 | 本轮未核实到 Lattice 自有商用代理/计费完整链路 | 必须实现后再售，不把“支持某模型 API”当作已提供官方服务 |
| 商业订单、权益、配额与退款 | 未核实到完整业务实现 | 先支持有限订单和人工核款，不从复杂订阅系统起步 |
| 安装信任与商业首页 | 签名及营销入口有缺口 | 签名和安装验证进入公开自助分发门槛；先受控试用 |

### 6.2 工程增量工作包

估算是对现有实现的计划，不是已完成报价。创始人确认需求和资源，指定实际工程执行者；可由 Codex承担后续开发，但本轮只交付文档，不修改产品。

| 任务 | 交付物 | 基线工时 | 验收 |
| --- | --- | ---: | --- |
| D1 共读入口与成果出口 | 一条首次任务路径；导出/重开沿用现有工作区 | 4h | 新用户不用理解 IDE 即可开始；失败有明确入口 |
| D2 官方模型路由 | 已认证、使用服务器端供应商凭据的官方调用路径 | 8h | 客户端不接收官方供应商密钥；按批准模型和材料范围运行 |
| D3 配额与成本账本 | 预留/交付/失败/退还次数、费用上限、并发约束 | 8h | 一次有效任务仅扣一次；失败费用入公司账，不重复扣用户次数 |
| D4 人工核款与权益管理 | 订单号、付款核验、开通、到期、撤销、退款记录 | 6h | 每笔款有且仅有对应权益，能处理漏开、重复核款和退款 |
| D5 透明发送与退出 | 发送范围预览、取消/超时、错误说明和恢复 | 4h | 未确认材料不发送；取消后不继续无界调用 |
| D6 发行与许可展示 | 签名配置、安装验证、About 与第三方声明核对 | 4h | 具体安装包来源、哈希、许可与实际构建一致；证书费用/交付另等外部条件 |
| D7 共读交付记录 | 关联来源版本、引用和笔记保存回执 | 3h | 不把工具口头报告当已保存；用户能回原文并重开 |
| D8 全链路验收 | 注册/试用/付款/开通/使用/退款/到期完整记录 | 3h | 真实流程可复核；模拟支付不作成交证据 |
| 合计 | 只围绕一个商品 | 40h | 允许发现后重估至 60h；超过 60h 必须砍范围或暂停，不默认加班 |

认证、计费、主体和签名有外部依赖；40h 不是保证 10 周上线。人工核款可暂代自动支付回调，但身份、服务器配额、材料边界和退款不能靠表格代替实际控制。

### 6.3 范围取舍

必须做：真实共读、来源核对、审阅写入、保存重开、官方连接、服务器端预算/次数、订单权益、人工退款、基础客服与退出。

保留但不主推：Notebook、代码、本地运行、插件、皮肤、Word/PPT、已部署共享库。低频功能不删除，也不占首发说明和新增开发排期。

后置：个人同步/灾备、多端、团队组织管理、机构 SLA、创作者市场、语音与其他搭子模式。后置功能不得写进当前 99 元商品。

## 7. 交易与履约流程：异常也要能结束

### 7.1 从体验到复购的动作链

| 环节 | 动作/责任 | 用户可见结果与留档 |
| --- | --- | --- |
| 预约与筛选 | 创始人确认平台、任务、材料权限、研究频率与自愿参与 | 说明官方体验和开源版差别；记录匿名用户 ID 和联系同意 |
| 体验 | 用户自行操作，主持人不代替完成；一次官方同规格共读 | 记录实际调用、正确回源、保存、帮助次数和失败，非 AI 路径单列 |
| 报价 | 服务通过门槛后展示同一 99 元/30 天商品 | 数量、范围、供应商、到期、退款、客服和免费替代选择全部在付款前可见 |
| 核款/开通 | 使用已确认可售该服务的商户通道；创始人人工核对交易号 | 拟定 1 个工作日内开通；无法开通即原路退款，不要求用户反复付款 |
| 消费 | 服务端校验账户、有效期和余量；先预留再交付结算 | 显示任务状态/剩余次数；不让客户端自由宣称自己已付费 |
| 保存 | 本地审阅写回；服务仅保留必要账本 | 用户看到文件保存回执，继续编辑与导出不需付费 |
| 客诉/退款 | 创始人记录理由、订单、处理时间、原路退款凭证 | 不要求交出私人论文才处理退款；禁止事后改权益 |
| 到期 | 服务提示准确时间；不给默认自动扣款 | 官方调用到期停止；本地成果、BYOK 和导出仍可用 |
| 续购 | 到期前一次服务性提示且允许拒收；用户主动重新买 | 区分已到期、主动再买、退款与失联；免费延长期不算续购 |

### 7.2 退款与故障的拟议规则

首单开通后 7 天内可申请全额退款，即使已经做过体验任务；这是内部拟议服务规则，不代替适用法律，正式售卖前由运营者核对更有利于消费者的强制要求。退款后关闭未消费官方权益，不处理或删除用户本地文件。

7 天后，平台原因导致已承诺服务不能继续时，按未交付次数占 20 次的比例计算未履行部分；无法确定时采用对用户更有利的处理，单笔总退款不超过实付。用户取消续购只是“不再购买”，不是自动续费解绑。

模型/网络失败不产生有效交付扣次；请求可能已有供应商费用，计入公司失败成本。单任务重试有上限，不能无限循环。失败成本逼近预算或供应商不可用时停新销售、通知现有用户、提供恢复或退款，不静默换差模型、降额度或再扣钱。

预售、候补名单、免费赠送、主持人代做、朋友口头表示愿意付费，都不计作商品真实成交。购买未开通也不能计作已履约收入。

### 7.3 不做复杂订阅系统的第一版

先人工核款、每包一次付款、人工处理退款和一次明确续购；每日核对交易—订单—权益—任务—退款五个账本。收款凭证/商户信息与正文研究材料分开保存。首批不自动续费、不年付、不终身、不搞无限量和充值返利。

收款、开通、退款流程虽人工操作，仍必须可重复、受权限限制、按单核对；不能把聊天转账截图直接当作可信服务端权益。

首批同时履约的付费账户最多 8 个；其他人进入不收款的候补名单。试用名额按本批批准总量、单账户一次体验和平台总费用共同控制，不能只限单账户次数却放任总支出增长。官方请求启动前同时核验账户余量、单任务资源、用户/平台费用预算和正在履行的订单；任何一项无法确认就不发起付费请求，并给出明确恢复或退款入口。所有这些都是待实现的服务端要求，不是现状功能。

## 8. 开始收费前的门槛与真实验证

### 8.1 五个门槛全部通过才收款

1. 产品：支持范围内的共读能真实完成；5 个目标用户里至少 3 人不靠代操作完成；事实解释和引用定位分别评估。已知文件破坏、未经授权写入和重复性错误引用未解决就不卖。
2. 模型与成本：冻结模型/版本/服务商及当前报价，25 个授权任务实例覆盖理解、来源、批注、保存恢复和失败；有实际用量账单并覆盖失败/重试。单用户最大可服务成本可封顶，而非只算平均一次成功请求。
3. 交易：商户/运营主体、销售资格与条款适用由运营者确认；订单开通、撤销、到期、退款和客服联系实际演练通过。没有符合服务范围的收款与退款通道就不付款。
4. 数据：用户在调用前看见材料范围和供应商；官方密钥不进入客户端；必要身份/交易记录与论文分离；供应商商业使用/转售、保留/训练政策与处理地域已核验并准确披露。
5. 交付：指定构建、安装、升级、导出和回退有证据；未签名期间只做创始人在场的受控安装，不引导绕过系统安全提示。公开自助安装须等有效签名与复测。收费时仍需遵守实际分发渠道规则。

没有门槛可以通过“人数少、测试环境、已经开源、以后补文档”豁免。也不把本地维护与完整云盘灾备捆绑：首个商品不存长期 PDF，但账户/权益账本仍要有必要备份和恢复能力。

### 8.2 首批付费试点

- 招募最多 8 位完成体验且符合目标任务的候选人，展示同一完整商品与价格，分别记录买/不买及理由；不能只挑已经说会买的人。
- 一笔真实自愿付款证明一个人的一次购买，不证明市场成立；本版继续投入线是至少 3 位用自己的钱全价购买并完成实际任务。付费体验与免费体验、研发好友和实际研究用户分组记录。
- 运行两个顺序队列；每个队列至少观察到真实使用和到期。第一队列若 8 位合格体验者无人购买，暂停新增商业开发，先访谈原因，不直接降价或扩平台。
- 到期人数不足 5 时只报逐人事实；两批首购者累计至少 5 人成熟后，建议全体成熟样本中至少 60% 主动再次付款（5 人时至少 3 人，6 人时至少 4 人）才进入扩量讨论。不能挑最好看的 5 人当分母。这是内部继续线，不是行业留存基准或 PMF 证明。
- 任一用户发生未处理的付款权益错误、材料泄露或文件损坏，停止新售并先修复/履约。
- 即使有人付钱，如果仍靠创始人代做阅读，成立的可能是人工服务需求；不能当作可自助扩张的软件生意。

## 9. 获客、营销与销售操作

### 9.1 首批只做一个渠道

现有同行、研究圈或真实关系的一对一邀请；不抓取联系方式、不批量群发、不伪装成普通用户发推荐。每周安排一个研究/销售时段，最多 2 次短访谈或 1 次完整观察。材料、讲解与活动只是同一渠道的辅助，不另建多平台日更计划。

过程目标：建立 15 位合格候选池，完成 6 次问题访谈，5 次独立任务观察，再向最多 8 位合格体验者完整展示商品。人数不足就如实记分母，不拉无关人填表。达到收费门槛之前只能邀请研究，不发购买入口。

### 9.2 可直接使用的话术

邀请：“我在做 Lattice，想观察你最近一次真实读论文的流程。我们重点看能否直接在 PDF 里提问、回原文核对、留下自己的笔记。约 30—45 分钟，你自己操作；材料发送范围和费用会在开始前说明，不参加后续购买也没关系。”

体验后：“哪一步比你原来方便？哪一步你不信任？你下次准备哪篇文章时会再次打开？请说一个真实任务，不需要给好评。”

正式报价：“本地开源版和自带模型仍然可用。官方共读包是 99 元/30 天，含 20 次指定范围的共读，不需你自己配 API。这里是模型、发送范围、额度、到期和退款说明。你可以继续用免费本地版，也可以按自己的需要购买；没有自动扣款。”

不买时：“主要是任务不需要、现有工具足够、材料不能发送、质量不足，还是价格不合适？我记录具体原因；不用为了支持项目购买。”

到期：“你的官方服务于[准确日期]到期，本地文件和笔记继续保留。如果你还需要同样服务，可重新购买相同包；不操作不会扣款。你是否希望不再收到该提示？”

不以“支持独立开发者”作为主要卖点来制造虚假的产品需求；赞助和产品订单分开。

### 9.3 内容和活动如何真正进入漏斗

只有真实操作链路已可展示后，每两周最多做一个 60—90 秒片段：一个原文难点 → 回源 → 一条被人修改的批注 → 笔记重开。只展示获准材料；预录明确标注，不冒充实时模型；描述支持范围和价格入口。

一场 45 分钟共读：5 分钟说明材料/AI边界；10 分钟用户提出问题；15 分钟原文核对和批注审阅；10 分钟保存与重开；5 分钟自愿反馈。最多每月一次，总准备/主持/跟进不超过 2 小时，替代该周研究时段。两场不能带来合格体验者，或挤压主线，就暂停。

不花广告费前先跑通：来源 → 体验 → 独立完成 → 完整报价 → 付款 → 交付 → 再买。访客、群人数、播放、GitHub star 和安装数只作上游信号。

### 9.4 公开增长的进入条件

两个成熟小队列存在真实购买和再买；核心流程可自助；将实际再买率换算为下一批所需新客数量后，支持工时、获客和失败成本仍可承受；公开安装/支付/隐私门槛通过。再一次选择一个内容或搜索渠道试两周，分别记现金 CAC 与创始人工时 CAC。达到 3/5 的小样本继续线本身不授权扩量。

首期不买量。后续若单客现金 CAC 无法由前三个服务周期的实际贡献覆盖，或支持产能不足，就停止该渠道。不能用未核实的长期 LTV 证明广告合理。

## 10. 单位经济与创始人产能

所有数值唯一输入见[商业假设模型](COMMERCIAL_MODEL.json)；本节是同一输入的可读解释。参数均为规划假设，尚无真实付费账单。账单到来后整体更新，不能只改对自己有利的一列。

### 10.1 一个 30 天服务包的账

| 项目 | 基准假设 | 口径 |
| --- | ---: | --- |
| 标价 P | 99.00 元 | 一次购买 30 天，不预收一年 |
| 支付通道费率 | 1% | 现金预算假设，不是支付商报价 |
| 退款准备率 | 5% | 内部风险预留，不是已观测退款率；真实退款可能远高于此 |
| 税务现金预留 | 5% | 预算占位，不是适用税率判断或完税结论 |
| AI | 15.00 元 | 20 次×0.60 元成功任务预算 + 3 元失败/重试预留；包括所有相关调用 |
| 每用户基础设施增量 | 2.00 元 | 不含固定底座；需以真实账单校正 |
| 单包现金贡献 C | 71.11 元 | 99×(1−1%−5%−5%)−15−2 |
| 现金贡献/标价 | 约 71.8% | 不等于含创始人劳动报酬的净利润 |

0.60 元不是已核实 API 价格，15 元不是“无限 AI”的成本保证。任务必须先完成质量与实际用量验证；若完整交付无法在该预算内完成，不能开放这个套餐。

失败预留不是允许减少已售权益。模型不稳定或费用预留耗尽时停止新售，承担恢复/退款，不要求用户为平台失败再次付款。供应商费率上涨时按队列履行已购包，未来订单另行重新验证，不能静默缩水。

### 10.2 每周期现金结果与规模

基准固定现金 F=300 元/30 天；不含一次性法务/签名/集成费，真实 F 未核账。下表另假设现金 CAC 为每位新增付费者 10 元；第一批纯关系邀请暂按 0 元，工时仍单列。

| 同周期付费者 N | 新付费者 A | 现金 CAC/人 | 支持时间 | 现金结余 N×C−F−A×CAC |
| ---: | ---: | ---: | ---: | ---: |
| 5 | 5 | 0 元 | 1.75h | 55.55 元 |
| 10 | 3 | 10 元 | 1.75h | 381.10 元 |
| 30 | 4 | 10 元 | 4.00h | 1,793.30 元 |
| 50 | 4 | 10 元 | 6.00h | 3,215.50 元 |
| 100 | 8 | 10 元 | 12.00h | 6,731.00 元；超当前支持预算，不能当单人可交付预测 |

支持假设：每位活跃付费者 6 分钟/周期，另给每位新付费者 15 分钟启动支持；计算式为 (6N+15A)/60 小时。两者是要被验证的假设，不能为了通过模型低报工时。免费试用的模型费、演示和研究工时需另外归入 CAC/固定试验预算，不能漏记。

50 人、4 位新增不是增长预测：如果前一期也有 50 人，维持该情景需要 46 人再买，即约 92% 的周期再买率。第 8 节的“5 位成熟者中 3 位再买”仅是小样本继续线，不能据此使用 92% 的财务情景。实际规划必须用成熟队列的留存推算 A，再核对现金与支持工时。

单个 30 天周期内，基准贡献静态覆盖固定现金约需 5 位付费者；此数字未计新客现金 CAC、一次性投入与创始人劳动，不能说“项目已盈利”或“养活创始人”。若为全部 32 小时/月按 100 元/小时计劳动报酬，50 人、4 位新增和上述参数才勉强留下 3,215.50 元；一次性投入及税费差异仍未覆盖。这不是收入承诺。

所有现金结果都是服务周期预算法：收款不等于已赚收入。开通和履约尚未完成、存在退款责任时保留相应资金；7 天首单全退窗口内不把收款拿去扩张。

### 10.3 时间上限和压力测试

每 32 小时保守分配：产品维护 12h、用户/获客 6h、支持 6h、经营/账务 4h、缓冲 4h。支持上限为 360 分钟，即 6N+15A≤360；没有新增时最多支撑 60 位，N=50/A=4 已用满该块。

| 变化 | 后果 | 决策 |
| --- | --- | --- |
| AI 成本从 15 升到 30 元/包 | 现金贡献降为 56.11 元；50 人/4 新增现金结余仅 2,465.50 元 | 不再宣称满足劳动报酬目标；先改服务范围/成本或另测价格，停止扩量 |
| 每用户支持由 6 升到 20 分钟 | A=4 时最多支持 N=15；同价下无法支撑 50 人 | 优先修上手/可靠性，或单独预算付费支持人力；不靠创始人加班 |
| 只有 60% 用户周期再买 | 维持 N=50 需 A=20；支持 10h，现金结余仅 3,055.50 元 | 小样本通过不等于可扩张；该情景超过支持预算且不覆盖 3,200 元劳动报酬，不能沿用低流失模型 |
| 固定现金从 300 升到 1,500 元 | 静态覆盖固定现金约需 22 人；覆盖 3,200 元劳动报酬且 A=4/CAC=10 至少需 67 人 | 超当前无新增支持上限；重做成本和服务产能，不称该方案已可养活创始人 |

| 供应商失败率明显升高 | 失败费用与退款责任同时增加 | 停新售、联系现有用户恢复/退款，保证已售责任优先 |

创始人 8 小时周的合理首期目标是验证小规模可持续现金流，不是承诺现象级产品、全职工资或团队规模。要超过人工产能，必须先自动化减少支持，或拿真实贡献支付新增人力。

### 10.4 初始现金和退出成本

## 14. 商业壁垒与产品质量路线

易复制的：API 接口、人格提示词、按钮、通用摘要。可积累的：真实任务完成与可靠来源定位、用户愿意保留的成果结构、低故障的版本/迁移、可解释成本和可信服务、反复改进的合法评测集、同行信任与维护能力。

用户可迁出的本地积累可能增强使用习惯，但不能靠锁文件或不透明记忆制造壁垒。开源维护本身也有成本；只维护一个公开主仓与清楚贡献规则，不把 star 或 fork 当市场占有率。

首期质量投入顺序：原文选区与回源 → 批注审阅与保存 → 当前任务模型回答/失败 → 重开与继续 → 连接/额度/账本 → 安装更新。额外 IDE、皮肤和语音只有在不影响首发任务时才维护，不用于冲淡关键故障。

没有真实付费、复购、贡献和自助交付证据，就不能称“现象级高质量商业产品”。合理结果可能是有用的开源工具、小型副业服务、可扩张产品，或验证后停止；不为这些结果编造概率或收入曲线。

周报只记录：实际小时、预算已用/剩余、主任务、匿名用户/订单分母、失败与处理、已成熟到期日、实际账单/支持工时、下一周唯一工程事项、继续/调整/暂停。联系方式与订单号受控保存，不把私人论文放入营销表。

停止线：

- 重复痛点没有出现，或用户在原流程更容易完成：不进入商业增量。
- 8 位合格体验者看清同价商品无人买：暂停新开发和获客；复盘价值，不从新品牌/新模式找借口。
- 实际服务无法按范围、成本和安全约束交付：停新售，先履行恢复/退款。
- 自然再次使用或成熟到期再买未出现：不买流量、不招增长团队。
- 费用超过批准上限、工程超过 60h 尚不能闭合，或支持时间持续超预算：砍范围/延期/停止，不默许投入。
- 全职/学业冲突让已售服务无法负责：提前停售，保留本地访问并完成告知/退款。

一个阶段失败可以留下有用的开源产品；不能用“愿景很大”把每条停止线改成继续烧钱的理由。
