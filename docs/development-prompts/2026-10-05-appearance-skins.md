# Lattice UI/UX 皮肤与个性化设计系统：开发委托

## 本窗口 Goal
将 Lattice 现有浅色/深色/系统模式升级为专业、贯穿工作区且用户可自定义的多风格皮肤系统。默认简洁风格保持成熟可用，新增至少四套有明确受众和完整浅/深色版本的风格；完成主题设计、可持久化选择、自定义与 AI 设计交换流程，经过真实页面和交互验证，交付主窗口可整合的实现。

## 用户意图与产品标准
Lattice 用于科研、学习、办公与开发。用户重视实际能力、简洁清晰、减少冗余 UI，也希望个性化审美和未来商业主题空间。00 后不是单一风格：可以从安静纸感阅读、柔和灵动、利落工业、克制数字夜景等方向选取四套，名称和色调由你专业设计。每套要有自己的 typography、色彩、surface、边界、圆角、密度、阴影和动效规则；不能只是换主色或给首页增加卡片。保持文献、公式、代码长时间可读。

先建立产品面清单与可实现设计规范，再构建，至少覆盖文件导航/多标签/工具栏、PDF 阅读与批注侧栏/浮层、Markdown 与公式、代码与 Notebook、AI Chat/Agent/证据/文件审查、设置/对话框/菜单/插件面板。语义色、焦点、选中、警告、禁用、加载与空状态要一致。PDF 原文及用户内容不能为了皮肤而变色变形；高亮颜色保持可区分。桌面实际交互必须完整，主题切换不得重挂载丢失文档/AI 任务。

## 必须落地的能力
1. 统一语义设计 token 和有版本的主题 schema/registry，区分皮肤与 light/dark/system；老设置迁移可靠，重开应用不丢选择，不闪回默认。恢复默认和损坏主题回退能用。
2. 至少五套完整皮肤（含现有默认），样式覆盖上述产品面。阅读内容字体与 UI 字体分离；仅使用已有或可合法本地提供的字体，不远程加载资源。尊重 reduced-motion、缩放和 keyboard focus；普通文字对比度至少 4.5:1，关键控件 3:1。
3. 在现有 ThemeSelector 与独立外观编辑组件中提供直观、克制的预览/应用/取消/保存入口。实时预览可撤销，取消和重开不应污染设置。窄窗仍能使用，别让设置本身成为炫技面板。
4. 用户可从内置皮肤克隆，自定义关键 token、密度/圆角/字体规则，命名/保存/删除自己的皮肤，导入与导出有版本 JSON。导入严格验证大小、值、未知字段和兼容版本；不允许执行脚本、远程 URL、全局危险 CSS 注入。导出重导入应能还原。
5. AI 辅助设计必须形成可用交换流程：一键获得包含 schema、token、产品面和可读性约束的设计提示词/主题模板；用户把 AI 生成的主题 JSON 导回，能校验、预览、调整和应用。若接入现有 AI 生成器，复用已有 provider/取消/审查机制并采用 mock 测试，不能再造 API 配置。
6. 未来付费主题用稳定主题 ID 与包/作者/许可证元数据兼容即可，不实施虚假商城、支付或锁住当前功能。
7. 提供开发者主题文档、示例包、token 对照与 AI 设计示例。为插件窗口明确 CSS 语义 token 接口，不另造插件 runtime。

## 验收与收敛
先记录可复现问题和视觉基线；建立至少“5 皮肤 × 浅深色 × 关键产品面”的验收矩阵。测试持久化/旧设置迁移、取消预览、导入导出、损坏 JSON、主题删除后回退、系统切换、并发设置写入不丢字段。浏览器真实操作切换主题/打开对话框/阅读含公式笔记/查看插件容器；截图必须看过，不能只截图留存。新皮肤不得出现透明文字、PDF 高亮不可见、菜单遮挡、布局跳动或 scroll/selection 丢失。必要时使用前端设计/测试技能，若 ImageGen 工具不可用，说明限制并用可检查的代码原生概念板完成视觉设计，不能因工具缺失停下。

## 执行方式与协作约束

用户已明确授权直接设计、开发并持续迭代，要求两个开发窗口各自设置 Goal；你就是其中一个正式开发窗口。第一步调用 get_goal，若没有未完成目标，使用 create_goal 创建下述本窗口目标，不设置 token_budget。完成设计、实现、验证、交接后才可标记 complete；不能把“写完方案”“代码能编译”当作已完成。持续处理失败和审查意见；不要为了省事只交付建议。遵循用户已给出的方向，常规可逆设计决定自主落实，无须重复询问是否开始。

先读项目 AGENTS.md、.agents/skills/lattice-project-flow/SKILL.md 和相关技能，使用中文沟通。涉及 Next.js 时先读 node_modules/next/dist/docs 中对应版本指南；优先官方文档与 Context7。用任务板记录 pending/in_progress/completed；若无 update_plan 工具，则在本窗口独立计划文档中维护。同一时间一项 in_progress。

这两个新窗口使用同一 Lattice 项目目录，共享现有大量未提交开发成果。禁止 git 提交、push、创建分支、reset、清理或覆盖他人文件，禁止远程部署。不要创建更多任务窗口。仅修改下述本窗口归属文件；需要修改共享文件时写 integration patch 和准确接入说明交给主窗口，不能直接编辑。其他窗口可能正在修改不同文件，不得将其临时类型检查失败修成覆盖对方成果。不要重写整个仓库、全局格式化或更新核心依赖。

主窗口拥有 src/components/settings/settings-dialog.tsx、src/lib/i18n/zh-CN.ts、src/lib/i18n/en-US.ts、src/components/renderers/pdf-highlighter-adapter.tsx、src-tauri/src/main.rs、package.json、lockfile、发布脚本和桌面安装。你对这些文件只读。本窗口需要的接入改动放在独立 handoff 文档并提供最小补丁；组件内部可以暂用局部双语字典，但正式全局翻译的增量交给主窗口。两个窗口可读对方计划/交接文件，禁止擅自编辑对方归属文件。直接整合的必要 UI 入口须在本窗口 handoff 说明清楚。
