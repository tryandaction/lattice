## 已定位的问题

- 使用完全合成的密钥与虚拟存储复现：持久层有值，重新启动模块后缓存为空；直接持久读取仍可取回。`initKeyStorage` 没有恢复 profile 前缀的密钥，设置面板和 provider 又只读同步缓存。
- 桌面密钥初始化仅识别 `__TAURI__`，需与已有 `isTauriHost` 的检测保持一致；初始化、早期写入与错误反馈也需要回归。
- `loadProfiles` 每次读取后写回，底层读取失败又可能被当成空值；需要避免加载覆盖编辑或将瞬时错误变成配置清空。
- 文件侧栏在面板和布局计算中均硬编码 14% 下限；需一起处理拖动、零宽恢复与持久化约束。
- 当前 agent 执行循环仅开放检索、索引读取、路径解析、计划任务与代码运行；已有 draft/proposal 与文件落盘能力没有成为完整的编辑工具链。
- 草稿落盘只支持新建/追加 Markdown，没有通用的、带原文件版本校验的编辑路径。
- PDF 子文档已有 manifest 与创建 helper，应复用真实目录定位；不能把普通创建空子文档也强行绑定为整篇论文证据任务。

## 本轮新增行为

- Chat/Agent 顶部状态条只保留运行状态、上下文和审阅入口；连接与模型只在输入区选择一次，Agent 工作流设置收进高级面板。
- 裸 `citation:...?...quote=...` 文本会在严格 AI Markdown 渲染前转成受合同校验的来源链接；代码块、已有链接和 HTML 不改写。
- 无可见续写增量时先提高一次可见输出预算；仍无进展才失败。空错误正文不再重复渲染，Retry 保留。
- 不按模型名称向自定义网关注入未经该连接验证的推理参数；空回答恢复统一到有界执行器，保留协议和模型输出上限。
- 新文件操作不把原始代码包成研究笔记元数据；更新操作需要 `expectedContent` 版本快照，文件变化则停止写入。
