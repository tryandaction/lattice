# 目录完整阅读：恢复与分批实施计划

目标：用户要求读取指定目录全部文章时，自动分批实际读取全部合规文件，重开/取消后可继续，目录过大不整批报错。相关检索和完整阅读保持用户意图的区别，不扩大资源预算、不用前100文件代表全目录。

当前状态：in_progress（本地目录v2已随3.1.4完成门禁、桌面安装与网页交付；云目录持续阅读扩展正在独立验收）。真实模型测试遵照用户要求不再执行。

## 已确认根因

1. `document-source-capture.ts` 完整枚举后再打开文件，超预算发生在首个阅读checkpoint写入之前。
2. 单文档任务v1的sources集合必须完全一致，不能简单轮换窗口继续；Composer恢复只保存当前sources而丢失原目录范围。
3. `source-index`当前数字list游标依赖内存生成器，search游标也只在内存有十分钟有效期，不能持久续读。
4. synthesis把每文件覆盖与每批摘要放进有限prompt，大目录即使读完也可能再次失败；session40条裁剪可能淘汰未完成任务。
5. “全部文章/所有论文”未全部纳入全文路由，部分请求可能误走相关检索。PDF子文件最终绑定只查看当前已打开sources，分批后必须使用持久账本的精确父版本。

## 执行顺序

- [x] 调查现有真实入口、checkpoint、预算及合成回归，独立只读设计审查；不声称已修复。
- [x] 新增目录级v2任务，记录workspace、授权selections、原任务、发现清单、每文件v1 checkpoint、缺口、实际snapshots和归约状态；保留单文档v1兼容。
- [x] 可恢复目录枚举：保存路径级复核轮次/待访问目录；新发现与旧目录复核公平推进，恢复不重扫相同前缀直至耗尽预算。不把持续变更目录声称为原子快照。
- [x] 依次打开一个有限源窗口，复用页/节阅读内核；严格提交checkpoint后推进。累计总字节不再导致整批失败；超限、损坏、无文本和不支持格式记录缺口，其他文件继续。
- [x] 调用/时间额度在一轮目录执行中共享；路径级文件验证队列避免续读被旧前缀耗尽预算。取消/切工作区/撤权/严格保存失败停止推进；可恢复任务不被40条历史裁剪。
- [x] 持久分层归约覆盖所有已完成批次，归约请求也按完整消息计预算；缓存校验children/范围/批次，固定SHA标识避免递归膨胀。UI区分发现/已读/待处理/失败/无文本/证据缺口。
- [x] 统一完整目录意图并接入Agent/Chat实际入口；自然“继续”恢复原目录。PDF子文件使用全部目录账本判断父集合并精确核验，多PDF不从最终单个引用猜父。
- [x] 网页大型任务账本从localStorage迁移到严格事务存储，验证>5MB写入、刷新回读及迁移/失败不覆盖历史；桌面原生存储保持兼容。冻结浏览器7,178,049字节任务回读通过，原生101文件正常关闭/重开通过。
- [x] 本地目录离线端到端及原生合成目录验收、完整质量门；3.1.4安装保留设置、同源码网页同步及桌面/手机壳层核验。
- [ ] 云目录从整批捕获迁入持久目录任务；元数据发现不下载全部正文，逐文件按成员权限和云修订读取，暂停/切文件后继续原目录；完成独立验收和下一版交付。

## 必须覆盖的反例

101嵌套文件与累计>32MB但单文件合规，末文件实际被分析；枚举重启/返回顺序变化、重叠目录、同名文件；checkpoint写失败/取消/撤权/切根不启动下一批；已读源变更/删除与新增文件不能保留错误完成标记；长PDF正确页/字符游标恢复；单个坏文件不丢其他成果；数百摘要分层归约；“继续”承接原目录；早期窗口父PDF的子文件版本正确且多PDF不误绑。

实施只使用项目合成数据和本地替身，不调用真实模型，不读取私人研究目录。多个专项agent已在限定文件范围实现意图、目录发现、任务保留、进度和父PDF判定；主线整合。当前证据及未交付边界见[目录阅读验收](../../tests/2026-10-22-directory-reading.md)。已发布3.1.4的云目录仍使用旧捕获路径；云扩展的新源码不能冒充安装版已交付。
