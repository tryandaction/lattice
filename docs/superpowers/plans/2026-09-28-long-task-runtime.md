# 长任务执行与会话材料连续性实施计划

目标：修复复杂 Chat/Agent 请求在持续工作时被固定总时限截断、长论文停在截断上下文、失败消息污染后续会话，以及状态栏串用旧任务的问题。用户已要求直接完成整轮优化；不另行创建分支或提交。

架构：保留现有供应商协议、原生字节通道、分批阅读检查点和引用校验，统一首个响应数据、响应空闲与总预算三个生命周期。复杂文档 Chat 复用既有只读研究流程；会话只保存授权材料指针，恢复时核对工作区并重新读取。

修改边界：src/lib/ai/profiled-provider.ts、native-http.ts、request-lifecycle.ts和src-tauri/src/ai_http.rs负责请求生命周期；chat-composer与现有document-source-capture负责只读长文路由；ai-chat-store保存会话状态；agent-status-strip只显示当前会话任务。沿用现有模型与API地址，不猜测替换模型，不绕过证据校验或写入审批。

验证顺序：先红灯复现固定时限截断、失败历史和旧会话状态泄漏；再修复并运行定向测试。模拟时间用于边界单测，真实本机HTTP使用慢首包及长流式响应验证；实际供应商验证须使用无私人文档的测试输入，凭证不进入日志。发布前运行qa:gate，比较最终程序和安装包。

独立审查补充：流式EOF不能代替协议完成事件；运行中消息持久化为未完成草稿，重载后不进入成功历史；本次@文件参与全文路由，普通材料清单与严格恢复路径分离。三项均已补充回归测试并修复。最终双端验收扩充为11项场景，包含意外重载、无打开标签的文件提问和提前EOF。首次质量门中止后修复了旧设置字段测试，最终产物必须使用重新运行的完整质量门。
