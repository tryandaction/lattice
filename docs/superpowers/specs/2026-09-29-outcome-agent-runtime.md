# 统一任务执行与结果交付

日期：2026-09-29。目标：用户直接表达研究、学习、计算和写作任务，系统选择必要能力，最终交付可核对的结果。入口数量不是能力指标。

## 一手工程依据

1. OpenAI, **Unlocking the Codex harness: how we built the App Server**, 2026-02-04：多个界面共享同一运行内核；持久线程、工具执行、审批与事件流属于运行时，不应在每个界面重做。原文：https://openai.com/index/unlocking-the-codex-harness/
2. Anthropic, **Effective harnesses for long-running agents**, 2025-11-26：跨上下文任务依赖增量进展、可恢复状态和实际验收；仅有压缩与高层提示不足以证明任务完成。原文：https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
3. Anthropic, **Demystifying evals for AI agents**：区分对话轨迹和真实环境结果，使用任务特定的判定标准。原文：https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents

下文是Lattice的工程选择与已实现边界，并非上述公司的原文建议或同等能力认证。

## 当前闭环

用户意图 → 当前任务与材料身份 → 原文提取/检索 → 受控工具与审批 → 回执/证据 → 答案合成 → 完整性与引用检查 → 无损展示、保存与恢复。

### 一个入口与可选交付设置
- 自动按用户当前任务选择策略，不根据论文中出现Python等词误切成代码任务。
- 手工策略仅影响当前请求；不把上次批注选择永久套用于下一次普通解释。写作语言、风格与模板偏好单独保留。
- 历史工作流ID兼容保存的session；前台无需把内部策略都当作独立agent宣传。
- 同论文深入追问可复用同工作区、路径及字节版本的全文检查点；切换新话题后不再附带旧论文正文。

### 原文证据
- 页/节文本在进入模型前构造片段目录，ID绑定路径、版本、内容和偏移。模型选择已有ID，程序回填原文。
- 引文仍必须在原材料中唯一定位，不能以模糊猜测或关闭校验掩盖问题。
- 一批含部分坏finding时，仅有界修复一次，然后保留好finding、隔离坏finding、记录证据缺口；完全无效不记为已完成批次。
- 阅读覆盖完成与证据完整分别记录；批注提案不等于已写入高亮。实际写入沿既有审阅和批准流程。
- 保存批注时，若渲染文本层因丢空格等原因无法严格匹配完整引文，使用同一PDF原始提取模型做完整唯一匹配，并从该模型生成坐标。不会缩短引文、忽略字符或把文本匹配成功冒称为写入成功。

### 长答案与失败恢复
- 传输区分首响应、空闲和总时限，合法协议结束事件才能完成。
- 达到输出长度上限时，保留已生成正文，在相同证据下有界续写。单次答案默认最多3段，禁止无限重试。
- 继续时保留未结束的文字/代码/公式，去掉显著且完全相同的前后缀重复。
- 深度不足检查仅用于触发一次补充说明。字符数和章节数不能证明科学正确性，也不能单独把完整短推导判为任务失败。
- 扩展失败、服务错误、用户停止与刷新均保留已收到草稿，并排除出成功知识历史。
- 正文内部Markdown分隔线属于正文；仅移除与当前session严格匹配的旧内部元数据尾部。

### 工具执行
- 显式计算/运行意图可以进入现有Python/JavaScript runner，但只能用类型校验过的工具参数，先经过审批。
- 工具回执绑定session、审批ID、计划步骤和完整代码参数签名；解释、代码围栏或‘已经完成’文字不是执行凭据。
- 批准后恢复原任务、计划、材料及工作区，输出作为不可信数据送回合成，不重新规划或重复运行。
- 已执行成功但最终综合失败，应仅重试综合；失败、拒绝、取消的执行不被伪造为成功。
- 已完成答案后清除执行恢复快照，后续草稿/记忆批准不重复触发答案生成。

## 验收分层

| 层级 | 可证明的事实 | 不能替代的事实 |
| --- | --- | --- |
| 单测与类型检查 | 预算、状态、校验、回执与恢复不变量 | 网关实际延迟、模型理解能力 |
| 本机HTTP与浏览器/桌面回归 | 真实协议、渲染、交互、断点与写入流程 | 真实模型完成复杂科研任务的质量 |
| 已存真实回答回放 | 既有4755字符答案无损显示 | 新模型请求的生成正确性 |
| 经授权的合成文本模型测试 | 指定模型/网关在指定试题上的表现 | 任意论文与无限任务质量保证 |
| 具体科研/办公任务验收 | 原文支撑、计算结果、实际文件及可恢复操作 | 仅靠‘PASS’标记或生成一份计划 |

评测记录必须说明模型标识、协议、是否mock、请求次数、首字/总耗时、结果检查和未覆盖范围。本机模拟接口明确标为local-fixture，不冒充glm或其他真实模型。

## 仍然存在的能力边界

- 本轮没有把Codex App Server或Claude Agent SDK集成为Lattice内核，当前仍使用可配置模型接口与Lattice运行时。
- 本轮新增的是受审批的已有runner执行闭环，不是任意文件系统或Office自动化。Word/Excel/PowerPoint完整生成编辑需要各自工具适配器和格式/内容验收，不能只用一个菜单或代码计划宣称已经具备。
- 运行中进程强制取消、严格文件沙箱、跨应用后台长期任务与关闭应用后持续执行，不能从本轮答案续写/检查点功能推断为已经实现。
- 扫描页、提取失败、歧义原文或供应商不可用仍可能阻断对应结果；应准确显示缺口，不能虚构引用或完成状态。

若进一步引入成熟编码内核，优先评估官方App Server这类拥有线程、工具、审批和事件契约的集成方式；Lattice保留研究材料及引用适配。应按实际能力、供应商支持、授权和结果评测决定，不把换SDK等同于换强模型。
