# 云端可用交付、团队 AI 与 GitHub 协作设计

用户已授权本窗口持续完成云端真实使用需要的功能，新增 GitHub 私有仓库连接及写入成员同步。保留本地界面；桌面安装包/releases 更新仍延期。实现、测试和可执行部署准备先完成；真实账号授权、第三方 App 凭据及付费模型配置不能编造。

## 增量方案

复用 Supabase Auth/Postgres/私有 Storage 和现有 Edge/Worker，扩展独立路由模块。所有用户内容访问继续转发用户 JWT 并由 RLS 决策，集成凭据绝不返回客户端。

1. 团队 AI：库管理员选择服务端预配置的模型，所有活跃成员按库使用；服务端代理调用，限定受控模型/域名/请求大小、并发和库级预算。AI 密钥仅环境 secret，服务端不得接受浏览器任意代理地址。未配置时提供具体配置状态，不显示虚假可用模型。前端接入既有模型接口及流式/非流式调用。
2. 协作审计：增加不可变事件表与触发器，记录文件内容版本、元数据、批注、评论和成员变化的真实 actor、时间、前后状态；当前库成员可看，普通客户端不能伪造/修改/删除事件。批注恢复通过已有 revision/CAS 创建新操作。库工具条直接打开审计面板，文本差异和批注 revision 可追溯。
3. GitHub：首选 GitHub App 的仓库级授权，支持私有仓库。OAuth code/state 与当前 Lattice 用户绑定；只接受官方 GitHub 主机，服务端保存加密 token。GitHub 不可变 user id 作为身份匹配依据；仓库 push/maintain/admin 权限映射为 editor，不凭 Git 提交作者名/邮箱提权，仓库读者不会自动成为 editor。未知 Lattice 用户绑定 GitHub 并验证仓库资格后自动加入。
4. GitHub 仓库关联与同步：库管理员关联被授权仓库及分支，展示同步状态、来源 SHA、作者归属；导入/拉取复用云 item/version，路径稳定，保留现有版本。向 GitHub 发布需显式动作和 SHA 基线，不静默覆盖。撤销集成只移除 GitHub 授权来源，手动成员权限保留；轮询/重新验证须有清楚的时效与失败状态。
5. 真实使用：检查现有线上服务健康与部署权限；准备迁移、Edge secret/公开配置及一步部署说明，能力允许时完成 Web/Edge 发布和隔离真实验收。GitHub App 注册/授权和模型凭据如果缺少，以明确步骤请求用户完成；不把本机测试代替上线。

## 验收

新增功能先行为测试失败再实现；真实 PostgreSQL/RLS、真实浏览器和合成两成员数据覆盖：越权、撤权、跨库、幂等、重放、并发、审计不可改、凭据不泄漏、GitHub 私有数据范围及上游失败。最终源码冻结后全量回归与生产 Web 构建，桌面阶段不执行。
