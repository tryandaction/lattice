# Lattice v3.0 科研工作台设计与验收

目标：把当前 local-first 工作台的 AI、证据和阅读编辑收敛为可靠科研闭环，并在质量门禁通过后生成本地 `releases/v3.0.0`。

## 执行边界

- 在当前工作区保留已有未提交实现。用户要求设计并落实完整迭代，继续可逆修复，无提交、分支、推送和远程部署。
- 不复制 Zotero、Obsidian、VS Code 的全部功能；对标具体行为：文本选择与批注一致、源文档可追溯、编辑保存不丢失、错误可恢复。
- 不升级核心依赖、不发送私人科研资料到外部模型。用确定性本地数据验证 AI 接口与交互；真实供应商请求另列验证边界。
- 不以测试通过代替桌面/浏览器实际交互，不把未验证发布候选称为稳定版本。

## 方案选择

1. **采用：修复已有共享契约和工作流。** 最小变更贯穿引用解析、导航请求、阅读器确认；保留现有存储与用户文件格式。
2. 暂不采用整套编辑器或 PDF 引擎替换：迁移与兼容风险远高于当前缺陷修复收益。
3. 暂不采用通用可视化 DAG 工作流系统：现有预设、笔记配置和 Agent 会话足以支撑本次科研任务，先把真实链路做完整。

## 用户体验契约

### AI 引用

- 回答下方最多显示三个来源入口；文件名和页码/行号为主，完整摘录按需查看。
- 点击来源直接导航到原文；失败才展示具体原因与恢复入口，不把“打开详情”当作成功定位。
- PDF 的页码、摘录、矩形保持同一目标语义。Markdown 支持跨行摘录；代码、Notebook 保留行号/cell 定位。
- 严格 AI 链接只能使用已绑定证据；不能将普通数字、无来源文本变成文件链接。
- 编码路径、摘录中的 `+`、`&`、`#`、`%` 往返不损坏；错误页码不能被宽松转换为有效引用。

### 科研工作流

- 利用现有 paper-reading、reading-note、literature-matrix、notebook-from-paper 等注册表，提供清晰入口。
- 用户能选择流程、查看预期输入与输出、配置笔记语言/结构/引文方式，并将设置真正送入执行路径。
- 保持草稿优先、写入确认和可停止执行；配置重启后可恢复。
- 不将“任务已创建”或“计划生成”误报为实际科研任务完成。

### 阅读与编辑

- PDF：选择、复制、高亮/下划线使用一致文本与几何；右键、缩放、侧栏导航、文件切换不重复创建或错绑批注。
- Markdown：特殊格式与源码编辑兼容；链接、数学、表格和代码块不相互破坏；导航定位可见。
- HTML/网页：明确源代码与预览模式，加载/失败状态正确，危险 URL 不混入工作区；保留已有外部浏览器路径。
- 代码：沿用现有 CodeMirror 与桌面 VS Code 集成边界，不承诺完整扩展兼容。

## 验收

1. 有根因和回归测试的缺陷修复，针对性测试、类型检查通过。
2. `npm run qa:gate`：lint、typecheck、文档检查、全部 Vitest、Next 生产构建、Tauri 构建。
3. 浏览器实际点击来源、PDF 选文批注、Markdown 编辑和 HTML 预览；相关桌面 smoke 以实际运行结果记录。
4. 发布版本元数据一致，用 `release:prepare` 生成安装包和哈希并校验；剩余限制写入发布说明。
