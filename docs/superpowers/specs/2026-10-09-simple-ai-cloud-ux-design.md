# Lattice 简洁 AI 与云端工作流设计

## 目标

让普通用户在不知道 Worker、Supabase、PATH、Harness、协议或运行环境的情况下完成三件事：打开云端小组库、拖拽上传文件、选择并使用可用 AI。高级用户仍可查看连接和诊断细节，但这些内容不进入主流程。

## 用户流程

### 云端小组库

默认入口只保留“打开云端库”“新建连接”“打开本机库”三个动作。连接面板支持粘贴邀请链接或连接配置文本；解析成功后自动填充公开端点和身份信息，普通用户只需要登录小组账号。现有逐字段连接表单保留在“高级连接设置”折叠区域，用于管理员或自托管部署。

进入云库后，文件区顶部只显示“上传文件”“上传文件夹”“刷新”三个主要动作。拖拽文件或文件夹直接进入统一上传队列，队列显示准备、上传、完成、失败和重试；权限、额度和离线状态使用短句提示，不把协议错误直接展示给用户。

### AI 来源和模型

聊天栏只保留一个“AI 来源”选择器和一个“模型”选择器。来源包括已配置 API、本机 Codex、本机 Claude Code，以及实际探测成功的其他本机适配器。运行环境、协议、可执行路径、权限边界移到高级诊断，不再占用聊天栏空间。

桌面端启动时自动探测已安装工具：优先使用显式保存的路径，其次使用 Windows 常见安装目录和用户级应用目录，最后使用进程环境 PATH。探测结果包含版本、登录状态、协议和可用模型。未探测到工具时提供系统文件选择器作为兜底；用户不需要手写 PATH。

模型选择器统一显示 API 与 Harness 的真实可用模型。没有模型列表时显示“使用默认模型”，不要求用户输入模型 ID。API 模型仍从已有 provider profile 读取，本机工具模型从探测结果或协议能力返回值读取。

### 错误和回退

连接或探测失败不会清空已保存配置。主流程显示一条可理解的错误和一个重试按钮；高级区保留技术原因。API 与本机工具之间可以切换，切换失败时保留原来源，不阻塞聊天输入。云库失败时本机库和已经打开的文件继续可用。

## 组件边界

- `src/lib/shared-library/connection.ts`：解析和验证邀请链接、连接配置文本，继续拒绝 secret/service-role 凭据。
- `src/components/shared-library/cloud-connection-panel.tsx`：简化连接入口；高级连接字段折叠。
- `src/components/shared-library/cloud-library-workspace.tsx`：统一上传队列入口和简洁状态文案。
- `src/lib/ai/harness/discovery.ts`：跨平台本机工具发现、候选路径、模型和登录状态归一化。
- `src-tauri/src/agent_harness.rs`：原生探测命令返回候选工具、模型和登录状态，不要求 PATH。
- `src/lib/ai/harness/types.ts`：扩展探测结果和来源模型类型。
- `src/components/ai/agent-runtime-settings.tsx`：从大块设置面板改为紧凑来源/模型选择器，高级设置折叠。
- `src/components/ai/chat-composer.tsx`：统一渲染来源和模型选择，移除主栏运行环境大块。

## 可靠性要求

- 配置重启后可恢复，探测失败不丢失配置。
- 显式路径优先于自动发现；自动发现只读，不修改系统 PATH。
- 每个上传文件独立记录状态并可单独重试，队列失败不影响已完成文件。
- 所有来源和模型选择都使用真实探测或已有 provider 配置，不伪造可用能力。
- 关键流程必须有组件测试、状态测试和至少一次桌面安装后冒烟验证。

## 不做的事情

- 不在主界面展示运行环境、协议、PATH 或权限 Profile。
- 不自动修改用户系统环境变量。
- 不把未知 DeepSeek Harness 当作已验证能力；如果只有 DeepSeek API provider，则显示为 API 来源。
- 不新增云端服务部署向导；邀请链接解析只消费已有服务配置。
