# LATTICE 云端功能：用户配置与产品发布

更新日期：2026-10-28。

> 产品运营方要按命令、平台入口和成功判断执行时，请以 [Lattice 产品运营上线手册](LATTICE-产品运营上线手册.md) 为主。本文保留产品用户配置边界和发布原则。

## 纠正旧说明

旧版“你先完成第 1～4 步”混淆了产品发布、个人账号和团队设置，不再适用。开发及发布 Lattice 不需要预置开发者的个人 GitHub 登录、仓库授权或 AI API key。安装包和网页不能携带个人登录态或模型密钥。

发布方负责统一云服务、产品级 GitHub App 和凭据加密基础设施。每位使用者在发布好的 Lattice 内登录自己的账号、选择自己的仓库，并按需要配置个人或团队模型。

## 普通用户操作

### 上传与共享

1. 点击侧边栏“共享库”，登录或注册自己的 Lattice 账号。
2. 点击“新建空库”填写项目名称，或通过邀请加入已有库。
3. 选择库后点击“上传到云端库”，选择文件或文件夹。
4. “本机已保存 · 等待同步”不代表上传完成；“云端已保存”才表示服务端已确认。
5. 在“成员与共享”邀请协作者并指定权限；文件继续用原有编辑器，版本和协作记录可追溯。

上传、共享和同步不要求 AI Key。服务不可用时应提示状态并允许继续使用本地库，不能要求普通用户搭建云平台。

### 连接自己的 GitHub

1. 选择“从 GitHub 创建云库”，或打开已有库的“GitHub 仓库”面板。
2. 点击“连接 GitHub”，在 GitHub 官方页面登录自己的账号并授权 Lattice App。
3. 安装或管理 App 的仓库访问范围，仅选择愿意授权的仓库；组织仓库可能需要管理员批准。
4. 回到 Lattice，选择已授权的公开/私有仓库并创建或关联云库。
5. 显式导入、拉取文件；发布到 GitHub 需确认，并通过 SHA 冲突检查。

每位用户授权自己的 GitHub 身份，不使用开发者账号。用户无需创建 GitHub App，也无需提交 PAT 或 Client secret。仓库写作者须分别绑定 GitHub 身份后才能匹配为 Lattice 协作者；无法匹配的身份不会被伪造为账号。

### 个人 AI

在“设置 → AI 提供商”配置自己的提供商、API 地址、模型和 Key，或使用本机模型/工具。云文件上的“云端 AI”把所选资料带入个人 AI 工作流。

个人凭据不会因上传文件自动复制到团队配置。当前桌面个人 AI 凭据保存在用户应用数据 Store；网页版使用浏览器持久存储的兼容编码，这不是操作系统密钥链加密，不能与团队云端 AES-GCM 密文存储混为一谈。

### 团队 AI

1. 库 owner/admin 打开“共享库 → 团队 AI → 添加团队模型”。
2. 填写名称、兼容 API 基址、准确模型 ID、团队自己的 API Key。多个模型 ID 用逗号分隔。
3. 当前接口支持 OpenAI Chat Completions 兼容的非流式文本调用，模型须支持 max_tokens；基址不含末尾 /chat/completions。
4. 按需勾选“启用本库团队 AI”，在“用量上限与费用预留”设置每日次数、每月额度、单次预留和输出 Token 上限。
5. 保存后显式发送一条合成问题验证上游连接。保存配置不表示 Key、余额、模型兼容性已验证。
6. “编辑”时 Key 不回显；地址不变可留空保留原密钥，换地址必须重新填写 Key。
7. 点击“移除”并确认停止后续调用；历史用量保留，已经发出的请求不能靠删除配置撤回。

普通成员可使用已启用模型，不能读取或修改凭据。团队 Key 经 HTTPS 提交到服务端，以 AES-GCM 随机 nonce 加密并绑定库/提供商 ID；数据库存密文，设置读取接口不返回 Key 或密文。平台调用时可解密，因此不是端到端加密。

默认批准 OpenAI、DeepSeek、Mistral、Groq、OpenRouter 的固定官方 origin；自定义网关由发布方审核后加入允许列表。禁止私网/IP 字面地址与重定向，产品服务器不能用作任意网络代理。实际协议/模型兼容性需验证。

额度是保守请求预留，不是供应商账单；失败或超时也可能计费。管理员应设置足够的单次预留，并在供应商侧设置实际消费上限。不使用团队 AI 时无需填写模型 Key。

## 产品发布方一次性职责

| 项目 | 产品发布方 | 使用者 |
| --- | --- | --- |
| 云服务 | API、数据库、私有存储、Auth、邮件、备份和公开入口 | 产品内注册、登录 |
| GitHub | 产品级 App、回调、权限、Webhook 和重试任务 | 授权自己的账号和仓库 |
| 团队 AI | 平台随机加密主密钥及配置接口 | 管理员在库内配置团队模型和 Key |
| 自定义网关 | 审核明确的 HTTPS origin | 在批准范围内选择网关 |
| 个人 AI | 设置和本机凭据保存能力 | 使用者自行配置，不上传到团队 |

TEAM_AI_ENCRYPTION_KEY 是随机生成的 32 字节 AES-256 主密钥（标准 Base64），不是任何人的 AI API key。必须独立加密备份，不能写进 NEXT_PUBLIC_*、安装包或共享文件；轮换前要受控重新加密。

TEAM_AI_PROVIDERS_JSON 只保留旧部署兼容，不是用户自配模式的必填项。不得为了通过预检填入开发者个人 Key；每个库无需手工运行 SQL 开启团队模型。

## 发布与验收

1. 发布方配置数据库、私有 Storage、鉴权、邮件、域名，平台权限留在发布系统。
2. 根据真实账本只应用缺失迁移，包括 202610270004_github_identity_unbind.sql 和 202610280001_cloud_team_ai_owner_config.sql；不重放已有初始化 SQL。
3. 部署主 API、GitHub Webhook 和重试入口，绑定产品级 App secret、GitHub 加密 key、HMAC 和任务 secret。
4. 设置 TEAM_AI_ENCRYPTION_KEY；自定义网关按需设置 TEAM_AI_ALLOWED_ORIGINS。无需设置个人/团队模型 Key。
5. 构建发布只带公开云库配置的网页：API URL、Supabase URL、publishable/anon key、显示名称与大小限制。
6. 用两个独立测试账号和合成库/仓库验证上传、共享、撤权、GitHub 私库、团队模型保存/更新/移除、额度和追溯。
7. 检查存储、响应、日志和发布产物不携带测试登录态或 Key。本地模拟测试不等于线上验收。

本地准备命令只生成部署材料，不发布或执行远程迁移：

~~~powershell
node "scripts/prepare-cloud-service.mjs" --storage=supabase
node "scripts/prepare-supabase-cloud-function.mjs"
node "scripts/cloud-production-readiness.mjs" --offline
~~~

平台字段、备份与恢复见 [云服务生产接入](cloud-production-github.md)。本文不表示线上已部署或真实账号验收通过。
