# PDF 稳定绑定验收

用户明确要求：批注和子文件绑定 PDF，而非绑定当前文件名或打开的目录；保留现有 `.lattice` 文件结构，并能找到实际存放地址。

## 本轮修复

- 批注注册表与 PDF 子文件位置注册表的读改写增加同实例串行队列。两个 PDF 同时打开时不再用各自的旧快照覆盖另一份绑定。
- 注册表使用可报告失败的持久化接口，存储不可访问时不能把写入当成已保存。
- 重命名/移动批注时只查当前根目录对应路径的候选，并只删除实际匹配的旧文件；不再清理所有文件名后缀，避免删除另一个同名 PDF 的批注。
- 复制/删除批注候选同样限制在实际根目录对应路径。原来“目标写入失败保留旧批注”的行为经回归确认，继续保留。

未改变 `.lattice/annotations` 与 `.lattice/items` 布局。PDF 的 `documentId`、内容指纹、原始位置登记和路径别名仍负责恢复，路径变化不是创建新文档的理由。现有产品的同内容复制件可共享稳定 Item 工作区，删除一个别名不能删除仍被另一个 PDF 使用的子文件。

## 实际工作台验收

使用合成 PDF 和浏览器真实 OPFS 句柄，不操作用户论文。正常主工作台与 Explorer 中完成：

1. 在子目录打开 PDF，高亮、通过原三点菜单填写备注，等待正常自动保存。
2. 点击新建笔记，确认 `Untitled.md` 落在 `.lattice/items/<原文档ID>/`，Item ID 与批注文档 ID 相同。
3. 打开父目录后重新打开该 PDF，原高亮和备注恢复。
4. 打开同名不同内容的兄弟 PDF，未出现原高亮或备注。
5. 切回子目录，原批注仍恢复。
6. 模拟应用外重命名 PDF，再从父目录打开，原批注及原子笔记可见。
7. 模拟应用外将 PDF 移到新目录，只打开这个新目录，原批注及原子笔记仍可见。

七阶段通过，页面/控制台错误0。实际子笔记仍位于原 `.lattice/items`，未复制一套新结构。证据：`.lattice-build/pdf-binding-lifecycle-browser-20261016/root-switch-results.json` 和11/12截图。

新增并发绑定与同名误删测试先出现3项预期失败；修复后5文件66测试通过。扩大PDF/批注/文件身份回归80文件915测试通过，源码定向ESLint零错误。最终发布门禁结果另记在总验收报告。

## 定位入口及边界

现有文件树可展开 PDF 子文件，右键“复制路径”；桌面端“在文件资源管理器中显示”使用文件句柄的实际完整路径，虚拟子节点仍持有实际 `.lattice/items` 文件句柄。网页由于浏览器权限边界提供实际工作区相对路径，不伪造系统绝对地址。

上述跨根恢复依赖原 `.lattice` 数据尚在、已登记根目录仍可访问。只把孤立 PDF 拷到另一台电脑而没有任何批注/子文件数据时，程序不能凭空恢复这些资料；共享库上传的 PDF 包会带上对应批注与子文件。磁盘写入失败会保留旧数据并报错，不宣称保存成功。串行队列保证同一应用实例内的注册更新，不是跨设备数据库事务。
