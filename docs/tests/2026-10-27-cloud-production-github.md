# 云端协作、团队 AI 与 GitHub 交付验证

日期：2026-10-27。仅完成源码实现、本地构建和隔离验收；新增能力尚未发布到生产。没有执行远端数据库迁移、Web/Edge 部署、桌面安装包更新或 Git 提交/推送。

## 已实现

- 保留现有本地工作区界面，管理面板增加团队 AI、GitHub 仓库和协作记录，文件工具条直接进入相关能力。
- 团队模型由服务端保存密钥；真实验证会话及成员、模型白名单、请求大小、库级每日次数与月度保守额度。PDF/Word 等来源复用既有提取器，最多附上 24,000 UTF-8 字节，并显示截断；无可读文本明确提示 OCR，不冒充读取成功。
- 不可变数据库审计记录操作者、时间和前后状态；覆盖版本、元数据、批注、评论与成员权限；历史入口打开指定内容版本。
- GitHub App PKCE 授权、一次性 state、加密过期令牌/刷新，私库访问限定为用户和 App 授权的交集。绑定稳定数字身份后按实际写权限授予 editor，不按 commit 姓名或邮箱提权。
- 签名 Webhook、投递去重、持久失败重试和受保护后台入口；撤权仅移除 GitHub 来源资格，保留手工成员。
- 文件显式导入/拉取/发布，保留目录和来源 SHA；内容版本、仓库及分支基线检查避免静默覆盖。元数据 RPC 在行锁下比较版本并合并当前服务器元数据，保留他人移动后的父目录。
- PDF 全部/自己/他人/指定成员显示筛选，内容版本比较和恢复沿用上一阶段实现。

## 真实生产仍需完成

已有公开云库配置已通过本地格式核查，不需要因此重建云库。预检确认 11 份迁移正文/hash 与生成包相符，但当前进程未提供服务端环境配置，也未取得生产迁移账本；这不等于断言远端原有配置不存在。

1. 账号持有人在 GitHub 创建/批准并安装 App，配置精确回调及 Contents/Metadata、适用组织 Members 权限和事件，服务端保管 App secret、加密 key、Webhook/job secret。
2. 运营者选择模型/上游并在平台绑定 TEAM_AI_PROVIDERS_JSON，设置目标库策略和费用额度；普通成员不应提供这些运营密钥。
3. 备份并核对生产 migration ledger，只应用缺失迁移。已有前八份的项目可审核生成包的 upgrade-20261027-existing-project.sql；不能重放已执行 SQL。
4. 发布主 API、独立 Webhook、独立 jobs 和 Web，启用五分钟重试调度，做真实双账号私库授权/撤权、Webhook 交付、AI 使用和隔离恢复验收。以上生产写入仍需明确确认，不能由本地测试冒充已完成。

操作字段和步骤见 [生产接入准备](../operations/cloud-production-github.md)。不要在聊天、公共配置或仓库中粘贴真实密钥。

## 明确边界

- 共享编辑为版本同步和可见冲突，未实现多人同光标实时编辑。
- PDF 隐藏仅影响自己的视图和按可见集合导出，不等同于向其他成员撤销读取权限。
- GitHub 成员同步依赖实际部署的 App 事件与重试调度；文件同步是显式操作，普通文件每个最多 1 MB，不声称已实现整库实时镜像或 LFS 内容下载。
- 团队 AI 是非流式文本对话，不自动执行文件修改；额度按每次尝试保守预留，失败不退款，不冒充上游实际账单。
